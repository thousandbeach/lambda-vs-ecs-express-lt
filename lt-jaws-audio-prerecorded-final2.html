でも、運用始めたら
Lambda が悲鳴あげてた。

01
コールドスタートで p99 崩壊
Node でも数百 ms、コンテナや重めだと数秒。SLO が持たん。
02
6 MB レスポンス壁で S3 逃がし地獄
Streaming で 200MB 行けるが、API GW 経由は結局 10MB で詰まる。
03
DB コネクション問題
RDS Proxy 入れても複雑さは残る。Supabase 直叩きも限界がある。
04
Warmer 入れたら「それもう常駐やん」
Provisioned Concurrency はアイドル中も課金される。
05
2025/8/1 〜 INIT 課金開始NEW
コールドスタートが「遅い」だけやなく「金もかかる」問題に昇格。
06
15 分制限、同時実行 1/インスタンス
I/O バウンドな API で「同時 1 」は根本的にミスマッチ。

Lambda に罪はない。ミスキャストしたのは俺や。

05 / 10

Lambda の本当の居場所

// where λ belongs
ここで Lambda は最強
  • SQS → メッセージ処理
  • S3 → ファイル処理(サムネ生成など)
  • EventBridge → イベント駆動の糊付け
  • Webhook 受信(単発、短命)
  • Cron バッチ・Step Functions のタスク
// misfit
押し付けると壊れる
  • 常時 warm な REST API サーバーI/O バウンド × 同時実行 1 = 悲劇
  • Next.js SSR(重い初期化)Vercel / Cloud Run のが自然
  • WebSocketLambda 単体では永続接続不可。API GW 経由でも相性悪い
  • DB コネクションプールの管理者
  • 大きなレスポンスを返す仕事

Lambda はイベントハンドラー。API サーバーちゃう。
